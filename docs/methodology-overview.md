# Methodology Overview

## Narrative stability

Narrative stability is the degree to which supplied messaging, within its reader-visible context, supports a sufficiently determinate consequential mental model and makes materially equivalent interpretations likely among the intended audience.

The construct is narrower than “good messaging.”

A narrative may be persuasive but unstable. It may be technically true but unstable. It may be elegant but unstable. Conversely, a compressed or provocative message can still be stable if the intended reader is unlikely to form materially different expectations from it.

## The diagnostic object

NSA examines whether readers can form a coherent model of several consequential elements:

- **Offering identity and organizing problem** — what this fundamentally is and what problem organizes the story.
- **Functional intervention** — what the product, service, or system actually does.
- **Actors and responsibility** — what is performed by the product, by people, or by other systems.
- **Scope and conditions** — where, when, and under what dependencies the claim applies.
- **Mechanism to result** — how the described intervention relates to the stated outcome.
- **Outcome and commitment** — what result is being promised and how strongly.

For each consequential element, the methodology distinguishes among:

- explicitly stated;
- contextually supported inference;
- unresolved.

## Interpretive convergence

The analyzer does not search for every imaginable alternate reading.

Instead, it asks whether there are **reasonable, materially supported alternatives** that would change how an intended reader understands evaluation, workflow, responsibility, deployment, purchase, or expected outcome.

A useful distinction is:

> Conceivable ambiguity is not the same as consequential interpretive competition.

If one reading is materially better supported, it can govern. If multiple materially different models remain similarly supported, the narrative is less stable.

## Continuity

Narrative stability also depends on what happens as the message expands.

Later explanation can:

- deepen an existing model;
- legitimately qualify it;
- materially revise it;
- or contradict it.

The methodology distinguishes explanation from correction. More detail is not automatically evidence of instability. The key question is whether the reader must consequentially revise the model they had already formed.

## Findings, not checklist penalties

The diagnostic system does not treat every triggered observation as a separate defect.

Multiple observations can arise from one underlying causal issue. A single ambiguity about autonomy, for example, might affect responsibility, expectations, and continuity without representing three independent problems.

The intended reasoning flow is:

**observations → causal clustering → finding → affected areas → downstream consequences**

This matters because otherwise a rich diagnostic taxonomy can accidentally become a double-counting engine.

## Context

Interpretation is evaluated relative to legitimate reader-visible context.

Relevant context can include:

- intended audience;
- audience expertise;
- artifact type;
- excerpt completeness;
- narrative position in the buyer journey;
- adjacent reader-visible material;
- communication posture.

Context changes the amount of interpretive work an artifact is expected to perform. It should not be used to excuse a materially misleading interpretation created by the supplied wording.

## Blind analysis and declared intent

A core design principle is to separate:

1. **outside-in stability analysis**, and
2. **alignment to the author’s intended takeaway**.

The outside-in pass should not be biased by knowing what the author hoped the reader would conclude.

Only after the blind assessment is frozen should intended meaning be compared with observed interpretation.

## Current status

The methodology is under active validation. The current development focus includes:

- testing whether diagnostic source domains are properly separated;
- validating finding attribution and anti-double-counting logic;
- improving anti-synthesis behavior;
- distinguishing insufficient assessment material from evidence of underdetermination;
- separating test relevance, execution, and result;
- versioning methodology and scoring safely over time.

This public overview intentionally omits the production prompt system, parameter taxonomy, scoring implementation, and evaluation corpus.
